# 3018: materialize.js: a comma-separated `Design-intent:` list is truncated to its first value

Surface: infra

## Current State

`liftMetadata` in `plugin/bin/lib/issues/materialize-format.js:119-138` lifts a record's body-metadata lines into the materialized header. The `Design-intent:` capture is `/^Design-intent:[ \t]*(\S+)/m` (`:131`). `\S+` stops at the first whitespace, so `Design-intent: quiet, minimal` lifts as `quiet,` (trailing comma kept, second value lost). `composeHeader` (`:157-169`) then writes `design-intent: quiet,` verbatim.

Multi-value intents are a supported shape downstream. `plugin/skills/design-wrapper/command-map.md:106` says "Multiple intents (comma-separated, e.g., `design-intent: bold, delightful`) trigger multiple dispatches." Polish reads the header's `design-intent:` for that dispatch, and so do `flow/manifesto.md:43` and `:57`. The run-level lever is a single-value enum in `plugin/bin/lib/policy-schema.js:95` (`none | bold | quiet | minimal | delightful | onboarding`).

In the reported run (plugin 6.136.0), the header read `design-intent: quiet,` and `config.yml` resolved to `quiet` only. Polish ran the `minimal` command only because the polish agent happened to re-read the record body. A mechanical header consumer would have skipped it.

## Deliverables

1. Change `liftMetadata`'s `Design-intent:` capture to the full same-line value: split on `,`, trim each value, drop empties, and validate each against the closed enum from `policy-schema.js:95` (read from there, not re-listed). The lifted value is a normalized list.
2. `composeHeader` writes the normalized list as `design-intent: quiet, minimal` (comma plus single space), the shape `command-map.md:106` documents. A single value is written exactly as today.
3. An unknown value (outside the enum), or a list that mixes `none` with any other value, fails materialization with a message naming the record and the offending value, the same hard-gate posture as other malformed header input. It never silently drops the value.
4. Decide how a multi-value header maps to the run-level `design-intent` lever, which is single-valued in `policy-schema.js`. Either have polish read the header list (not the lever) for dispatch, or document in `flow/manifesto.md` that the lever is a run default and the header list is authoritative per record. Pick one, and make the manifesto's Design-intent row (`manifesto.md:57`) state it.

## Acceptance Criteria

- A unit test lifts `Design-intent: quiet, minimal` and asserts the header line `design-intent: quiet, minimal`. Prove it goes red against the current `\S+` capture.
- Unit tests cover: a single value (unchanged output); extra spaces and a trailing comma (`quiet ,minimal,` → `quiet, minimal`); an unknown value (materialization fails, naming it); `none, bold` (fails).
- A bare `Design-intent:` line with no value still lifts nothing. The existing refs-#357 same-line-only behavior is pinned by an unchanged test.
- The polish dispatch path receives both intents for a two-value header, asserted by a test or conformance check on whichever consumer Deliverable 4 picks.
- `npm test` passes in full.

## Release Note

Records with more than one design intent now carry every intent into the build, so polish runs each one instead of only the first.

## Technical Approach

Keep the change local to `liftMetadata`/`composeHeader`. Capture with `(.+)$` like `Ui-stack:` already does at `:133`, keeping the `[ \t]*` same-line guard, then normalize. Source the enum from `policy-schema.js` so the two cannot drift. Hard-fail on invalid values rather than filtering: a silent drop is the exact failure this record reports, one level down.

### Key Files

- `plugin/bin/lib/issues/materialize-format.js` — `liftMetadata` `Design-intent:` capture (`:131-132`), list normalization and validation; `composeHeader` output (`:169`)
- `plugin/bin/lib/policy-schema.js` — enum source of truth (`:95`), read not modified
- `plugin/skills/flow/manifesto.md` — Design-intent lever vs. per-record header list (`:43`, `:57`)
- `plugin/skills/design-wrapper/command-map.md` — reference for the documented multi-intent shape (`:106`)

## Gotchas

- The refs-#357 comment at `materialize-format.js:124-128` explains why every capture uses `[ \t]*`, not `\s*`. Keep that guard on the new capture, or a bare `Design-intent:` line will swallow the next line.
- `yamlSafeScalar` (`:146`) is applied only to `ui-stack`. A comma-separated list contains no `:` or `#`, so it needs no quoting, but do not route it through a YAML-list syntax that other header readers do not parse.
- Records already materialized with `design-intent: quiet,` live in old run dirs. Readers must not crash on that legacy shape. Treat a trailing comma as a trimmed list on read too, if any reader re-parses the header.
