# 4026: Collapse per-step bookkeeping into self-logging CLIs and a single phase-exit call

Evidence: 14-day transcript analysis of this repo (176 main sessions, 5,599 subagent transcripts, 132 archived timing.json files, ~286k tool calls), 2026-10-24.

## Current State

Every tool call is a model turn over a p50 276k-token context (p90 428k), costing ~4–12 s. Bookkeeping takes a large share of those turns: 11.4k `log-decision.js` calls in 14 days (~75 per pipeline) and ~23k run-dir CLI calls overall (8% of all tool calls, ~10% of context tokens).

Deterministic CLIs already compute most decisions (`resolve-policy.js`, `flow-preflight.js`, `claim-targets.js`, `materialize.js`, `pr-checklist.js`); the model then re-narrates each one with a separate `log-decision.js` call. #3968's build agent made ~17 `log-decision.js` calls and 3 separate checklist pushes, plus individual record-worktree / record-pr / push / checklist calls at every phase exit.

## Deliverables

1. Every bin CLI that makes or applies a decision appends its own decisions.md entry (via `lib/log-decision/append`) when given `--run`; skills drop the matching `log-decision.js` instructions.
2. `log-decision.js` accepts many entries in one call (an entries file), for model-judged decisions batched at phase end.
3. A `phase-exit` CLI — commit check, explicit `git -C` push, PR checklist flip, record-pr / record-worktree, post-push merge-state check, and the decision entry — in one call with one JSON result, replacing the phase-exit prose at every call site.
4. Skill prose migration with conformance tests per `docs/skill-authoring.md`; expand-contract for any consumer of the old call shapes.

## Acceptance Criteria

- [ ] `log-decision.js` invocations per pipeline fall from ~75 to 10 or fewer, measured over 10 runs.
- [ ] Each phase exit is one tool call; the phase-exit CLI has a test for each sub-step's failure branch.
- [ ] decisions.md parity: a fixture pipeline produces the same entries (ignoring timestamps) before and after.
- [ ] Median tool round trips per pipeline (timing.json) fall by at least 25% across 10 runs (baseline 407).

## Release Note

Pipelines spend far fewer turns on bookkeeping: tools log the decisions they make, and each phase exit is a single step.

## Technical Approach

### Key Files

- `plugin/bin/log-decision.js` — multi-entry input
- `plugin/bin/pr-checklist.js` — called from phase-exit
- `plugin/skills/_shared/git-discipline.md` — phase-exit cites the CLI
- `plugin/skills/_shared/pr-checklist-refresh.md` — phase-exit cites the CLI
- `plugin/skills/_shared/auto-decision-log.md` — self-logging CLIs
