# 3659: Wrap-up engine plan reads repo facts from the main checkout when run in a linked worktree

Origin: reflect light from #3598

Defer-reason: tangential

## Current State

`plugin/bin/wrap-up-engine.js` `plan` resolves its fact-gathering root with `resolveRepoRoot(process.cwd())`, which returns the directory above `git rev-parse --git-common-dir`. From a linked worktree that is the MAIN checkout, not the worktree. The root was written for telemetry (anchor to the main checkout), and #3017 reused it for `gatherFacts({ cwd, base })` as well, so `plan` run from a worktree computes `git diff --name-only {base}...HEAD`, the renamed/deleted list, the journey `files:` overlap, and the `docs/`/`CLAUDE.md` filesystem facts against the main checkout's HEAD and tree.

Observed on #3598 (run 2026-10-19T201721-record-3598): `plan` run from the dispatch worktree listed two renames of archived run-dir spec files (3571, 3573) as the `references` row candidates and returned an empty journeys overlap list, although the branch diff held only added and modified files and one journey it had edited. The wrap-up judge had to override both rows by hand. A gate that is wrong this way can also read closed when it should be open.

## Deliverables

1. Split the two uses of the repo root in `plugin/bin/wrap-up-engine.js`: telemetry keeps anchoring to the main checkout, while `gatherFacts` (and `buildJourneyFrontmatter`) read the worktree root, `git rev-parse --show-toplevel` from the process cwd.

2. Add a regression test that runs `plan` from a linked worktree whose diff differs from the main checkout's and asserts the facts come from the worktree.

## Acceptance Criteria

- `plan` run from a linked worktree reports `changedFiles`, `renamedDeleted`, and journey overlap from that worktree's `{base}...HEAD`.

- Telemetry still lands under the main checkout's `.claude-tweaks/`.

- The new test goes red on the current code and green after the change.
