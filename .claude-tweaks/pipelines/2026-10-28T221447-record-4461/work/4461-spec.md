# 4461: reconcile: one branch with more than 10 associated PRs fails the whole bulk PR screen, silently disabling archive-branches and remote-prune

**Related:** #1082

Origin: /claude-tweaks:tidy close-out 2026-10-27 (run 2026-10-27T055458-tidy-standalone)

Defer-reason: tangential

## Current State

`resolvePrStatesBulk` (`plugin/bin/lib/reconcile/pr-state.js`, line 385 on main) returns `network-failure` for the WHOLE screen when any single branch's `associatedPullRequests(first:10)` page has `hasNextPage`. On 2026-10-27 the local branch `worktree-sweep` (a reused session branch name, 15 merged PRs) did exactly that: every one of 441 in-scope branches reported `skip:network-failure` in `archive-branches`, and `remote-prune` reported `pr-screen-failed`. GitHub rate limits were fine and every GraphQL chunk returned exit 0 in about 1.5 s.

## Deliverables

Approach: Bound the failure to the branch that caused it: a truncated `associatedPullRequests` page puts that branch on a per-branch fallback (the REST `pr list --head` resolver), and the rest of the chunk keeps its screened state. Distinguish the reason from a transport failure in the result vocabulary.

1. Resolve a truncated-page branch individually (per-branch confirm) instead of failing the chunk, keeping the module's "never a silent partial" posture for genuinely incomplete responses (missing alias, GraphQL errors).

## Acceptance Criteria

- With one branch having more than 10 associated PRs, `archive-branches` and `remote-prune` still classify every other branch in the same pass (test fixture).
