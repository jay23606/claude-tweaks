# 3015: SubagentStop contract check fires on an intermediate yield while in-turn Agent completions are still pending

Surface: infra

## Current State

The SubagentStop hook (`plugin/bin/lib/hooks/subagent-stop.js`) grades a dispatched subagent's reply against the Subagent Contract: the last non-empty line must read `STATUS: {DONE|DONE_WITH_CONCERNS|NEEDS_CONTEXT|BLOCKED}` (`CANONICAL_RE`), and a non-compliant reply is blocked and retried in-run.

A subagent running `/claude-tweaks:review` Step 3's lens fan-out launched 8 in-turn `Agent` dispatches and yielded with a one-line progress note while 5 were still pending — the pattern the dispatch prompt sanctions, since the harness delivers the completions back into the same turn sequence. The hook graded that progress note as the final reply and blocked, forcing the subagent to emit a `STATUS:` line mid-run, before its review, polish, and wrap-up work had run. A dispatcher reading that first `STATUS:` line would treat an unfinished run as complete. Reported on plugin 6.136.0.

Two partial mitigations already exist and did not cover this case:

- #2041's `asyncWaitCheckpoint`: skips grading only when the reply immediately follows an async signal in the transcript (`isAsyncWaitSignal`: an `isAsync: true` Agent launch result, or a `task-notification`). A yield composed after other tool calls has no such signal right before it.
- #2714's `INTERIM_STATUS:` marker (`isInterimProgressReply`): an opt-in trailing line that exempts a reply. It works only when the dispatch prompt tells the subagent to use it; only `_shared/subagent-output-contract.md` and `reflect/full-mode.md` mention it, and review's lens fan-out does not.

Neither knows whether the subagent still has dispatches outstanding.

## Deliverables

1. The hook counts the subagent's own in-turn `Agent` dispatches that are still pending at the time of the reply — async launches seen in its transcript minus completions delivered as task notifications — and skips grading (or logs it as advisory only) while that count is above zero.
2. A reply with nothing pending is graded exactly as today, including the existing #2041 and #2714 exemptions.
3. Transcript parsing stays defensive: an unparseable or unexpected shape falls back to today's grading, never to a blanket exemption.

## Acceptance Criteria

1. A transcript fixture where a subagent launched async `Agent` dispatches and yields before all completions arrive is not blocked and is not forced to emit a `STATUS:` line.
2. A transcript fixture where every launched dispatch has completed, ending in a non-compliant reply, is still blocked.
3. A reply ending in `INTERIM_STATUS:` and a reply right after an async signal behave as today.
4. The fixtures are taken from a real transcript's line shapes, not invented; the hook's existing tests pass.

## Release Note

Subagents that pause while their own background agents are still running are no longer forced to report a final status early.

## Technical Approach

Extend the transcript scan `subagent-stop.js` already performs (`lastAssistantText`, `isAsyncWaitSignal`) to collect launched async dispatch ids (from the Agent tool result) and completed ids (from task-notification entries), then exempt the reply while any launched id lacks a completion. Correlate by id rather than by count where the transcript carries one.

### Key Files

- `plugin/bin/lib/hooks/subagent-stop.js` — pending-dispatch count and exemption
- `plugin/skills/_shared/subagent-output-contract.md` — note that pending in-turn dispatches exempt a yield, beside the `INTERIM_STATUS:` rule
- `tests/bin-lib/hooks/contract-retries.test.js` — existing SubagentStop coverage; add the new fixtures
- `docs/hooks.md` — SubagentStop behavior description

## Gotchas

- Confirm the transcript field shapes (async launch result id, task-notification payload) against a live transcript before writing the parser; #2041's own comment notes its shapes were verified that way.
- A dispatch that never completes would exempt the subagent forever; bound the exemption (for example, only while the launch is newer than the reply, or a ceiling on the number of exempted stops) so a hung child cannot hide a real contract violation.
- Adding the `INTERIM_STATUS:` instruction to review's lens fan-out prompt would also fix the reported run, but leaves every other nested dispatcher exposed; the mechanical count is the general fix, and the prompt instruction can be a follow-up.
