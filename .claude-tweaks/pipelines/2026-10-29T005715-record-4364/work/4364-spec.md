# 4364: Keep the express-lane sample review from re-filing findings after a partial capture failure

**Related:** #4365

Origin: #4025 build (express lane) — fix-wave re-review Minor; refs #4025

Defer-reason: genuinely-larger

## Current State

#4025's express-lane post-merge sample review (`plugin/skills/_shared/express-lane.md`, Post-merge sampling step 2) files each confirmed finding with `/claude-tweaks:capture`, then posts the `<!-- run-comment: express-review -->` marker comment only when every finding filed. A capture that fails after earlier captures for the same PR succeeded leaves the PR unmarked, so the next sweep reviews it again and can file the already-filed findings a second time.

The shaped-body capture branch never passes a `fingerprint` (`recordPayload` accepts one; the health sweeps dedupe by it), so there is no filing-time dedupe to lean on. Flagged as a Minor by the #4025 fix-wave re-review.

## Deliverables

1. Make a re-review of a partly-filed sampled PR skip findings already filed for it — e.g. a per-finding fingerprint (PR number + lens + finding key) passed through the capture filing and checked before filing, or a non-marker progress comment listing filed records that the next sweep reads.

2. Pin the chosen mechanism in `tests/express-lane-prose.test.js` (or a CLI test if it lands in `plugin/bin/lib/express/`).

## Acceptance Criteria

- [ ] A sampled PR whose first sweep filed some findings and then failed a capture files no duplicate record on the next sweep.

- [ ] The marker comment still posts only once every finding is filed.

## Release Note

Express-lane post-merge reviews no longer risk filing the same finding twice after a partial filing failure.
