# 3503: Reconciler archives a run whose PR merged before all of its records were built

**Related:** #3412, #3416, #3249, #3311

Origin: dispatch close-out of PR #3439 (#3412), 2026-10-18

Defer-reason: pre-existing-outside-diff

## Current State

- A multi-record `/flow` run can have its PR merged while one of its records is still being built. On 2026-10-17, PR #3348 (run `2026-10-17T062549-spec-3307-3308-3306-3309-3310-3311`) was squash-merged at 18:33Z, on explicit human instruction, closing #3306-#3310 only; its body's `Fixes #3311` had been changed to `Refs #3311`. #3311 was still mid-build in the run's locked worktree `skill-size-limits-3230`.
- About two minutes later (18:35:05Z) the reconciler closed and archived the whole run: its archived `run-state.json` reads `status: clean`, `worktree: null`, and the directory moved to `.claude-tweaks/pipelines/archive/`. The owning session's #3311 work (full build plus a review fix wave) was still unpushed at that point.
- #3412 (merged as 5cf9073d3, PR #3439) fixed the claim half: `release-merged.js` now releases only claims whose issue the merged PR actually closes. It did not touch `plugin/bin/lib/reconcile/archive-merged.js`.
- On main, every merged-PR archive path in `archive-merged.js` keys only on the PR being MERGED plus console/staged state: `decideArchiveCore` (archive once MERGED and the console is resolved, or `console: none` with nothing pending in `staged/`, #3249), and the by-number fallback in the main loop (the same rule via `resolvePrStateByNumber`). Neither checks whether the merged PR closed every record in the run's `manifest.yml`, so a partially-shipped run is treated as finished.
- #3416 is a different trigger with the same symptom: a reused branch name resolves to an earlier merged PR, so a run whose own PR is still open gets archived.

## Deliverables

- Before archiving a run on merged-PR evidence, check that the merged PR closes every record the run claims: the manifest's spec ids for a multi-record run, or the single record for a singleton. Use the closing-issue data #3412 added to `pr-state.js` (`closingIssuesReferences`). When any record is not closed, skip archival with a distinct tracked reason (e.g. `merged-partial`) and leave `run-state.json` untouched (no `status: clean`, no `worktree: null`).
- Apply the same check on every merged-PR archive path in `archive-merged.js`: the branch-joined path through `decideArchiveCore`, and the by-number fallback.
- Keep #3249's behaviour for a merged run whose PR closes all of its records: it still archives with no manual step.

### Technical Approach

Read the run's record set from `manifest.yml` (`multispec.specs[].id`), falling back to the run's single record id for a singleton. Pass the merged PR's closing-issue numbers (from `pr-state.js`, extended by #3412) into the archive decision, and make it return `skip` with a `merged-partial` reason when the set difference is non-empty. Keep `decideArchiveCore` pure by having the caller supply both sets. Decide whether `merged-partial` belongs in `STRUCTURALLY_STUCK_REASONS` (escalate) or should wait for a later PR; it should not freeze silently.

#### Key Files

- `plugin/bin/lib/reconcile/archive-merged.js` — `decideArchiveCore` and the by-number fallback: add the all-records-closed check
- `plugin/bin/lib/reconcile/pr-state.js` — reuse the closing-issue data #3412 added; extend the by-number read if it lacks it
- `tests/bin-lib/reconcile/archive-merged.test.js` — partial-merge, full-merge and singleton cases

### Gotchas

- Coordinate with #3416, which changes how the run's PR is resolved in the same main loop. Land whichever goes second on top of the other's PR lookup.
- A run legitimately split across two PRs will now wait for the second PR before it archives. That is intended, but the skip reason has to make it visible rather than looking stuck.

## Acceptance Criteria

- [ ] A run whose PR is MERGED but whose manifest lists a record the PR does not close is not archived. Its `run-state.json` keeps its status and worktree, and the skip reason names the unclosed record(s).
- [ ] A run whose PR is MERGED and closes every manifest record still archives exactly as today, on both the branch-joined and by-number paths.
- [ ] A singleton run (no multi-record manifest) behaves as today when its PR closes its record.
- [ ] When closing-issue data cannot be read (gh failure), archival is skipped with a transport reason, never assumed complete.
- [ ] A regression test reproduces the partial-merge archive and fails on the pre-fix code.
- [ ] `npm test` passes.
