# 3572: Don't adopt a clean worktree whose branch's PR already merged — create a fresh one instead

Origin: reflect light from #3536

Defer-reason: tangential

## Current State

`plugin/skills/_shared/worktree-setup.md`'s Adopt-or-create rule tells an already-isolated session to adopt its current worktree whenever `git status --porcelain` is empty. It never asks whether that worktree's branch is already merged. In #3536's run the session was sitting in `flow+spec-3352-3464`, whose PR #3526 had squash-merged minutes earlier. The tree was clean, so the rule said adopt.

Adopting would have built #3536 on a branch carrying #3352/#3464's pre-squash history, opened a second PR from an already-merged branch, and left the run in a worktree that the reconciler's post-merge reap treats as reap-eligible. The controller deviated by hand (`git worktree add` from `origin/main`, then `EnterWorktree(path)`) and logged the deviation. A headless dispatch that follows the rule literally has no such judgment.

## Deliverables

- In Adopt-or-create's **Already isolated** branch, add a merged-branch precondition next to the clean-tree check: when `gh pr list --head {current-branch} --state merged` returns a PR (or the branch tip is an ancestor of `origin/{integration-branch}` with commits of its own), do not adopt. Create a fresh worktree from `origin/{integration-branch}` the way the dirty-tree path does. Fail open (adopt as today) when `gh` is absent or the lookup errors, and log which path ran.

- A `tests/` conformance pin that the Adopt-or-create section names the merged-branch precondition, following the neighbouring `worktree-setup` pin tests.

## Acceptance Criteria

- `grep -nF 'merged' plugin/skills/_shared/worktree-setup.md` shows the new precondition inside the Adopt-or-create section.

- The new pin test fails when the precondition sentence is removed, and passes with it.

- `npm test` passes, including the composed-bytes ceiling for every compose call site of `worktree-setup.md`.

## Release Note

A run started from a worktree whose PR already merged now gets a fresh worktree instead of reusing the merged branch.
