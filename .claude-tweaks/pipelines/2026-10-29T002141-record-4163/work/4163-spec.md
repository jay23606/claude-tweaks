# 4163: Console backfill: settle Review Console residue under work-backend: local-files

Surface: infra

**Related:** #3813, #4125, #4162

Origin: #3950 final whole-branch review, finding I2 (PR #3992)
Defer-reason: genuinely-larger

## Current State

`/claude-tweaks:tidy`'s console backfill mode (`plugin/skills/tidy/console-backfill.md`, CLI `plugin/bin/console-backfill.js`) settles Review Console residue left in archived runs: it files records, posts digest lines, and rewrites each `console.json`. Its filing and digest steps go through GitHub Issues only (`gh issue create`, `gh issue comment` on the digest issue), so Step 3's backend gate stops any project whose `work-backend` is not `github-issues` with:

`HELD — console backfill needs work-backend: github-issues; local-files support is tracked as the backlog record "Console backfill: settle Review Console residue under work-backend: local-files"`

A `work-backend: local-files` project therefore keeps every unreviewed console item forever, and its session-start residue notice never clears except by a blanket `console-residue.js --ack-all`.

## Deliverables

- Console backfill runs under `work-backend: local-files`: filings become local record files through the same writer `/claude-tweaks:capture` uses under that backend, and digest lines append to the local digest the materiality floor names for that backend (`_shared/materiality-floor.md`).
- Filing dedup (claim fingerprint and `consolebackfill-item` marker) and digest dedup read the local records and local digest, so the crash-resume guarantees hold as they do on GitHub.
- Step 3's backend gate passes `local-files`; the HELD line is removed or narrowed to backends that remain unsupported, and its pin in `tests/tidy-console-backfill-conformance.test.js` is updated.

## Acceptance Criteria

- On a `local-files` fixture project with one archived run holding a confirmed finding, a digest-bound finding and a dismissal, a backfill pass leaves one local record, one local digest line, and a `console.json` whose items all carry a `ref`.
- A second pass over the same fixture writes nothing.
- A pass interrupted after the record write and resumed after a claim-text change reuses that record rather than writing a second one.

## Release Note

Console backfill now settles Review Console residue in projects that keep work records as local files.

## Technical Approach

The CLI already plans from data the procedure hands it, so most of the change belongs in the procedure. `console-backfill.js dispose` takes `--existing` (today a `gh issue list --state all --json number,title,body` array) and `--digest-comments` (the digest issue's comment objects) (`plugin/bin/console-backfill.js:10-22`). Under `local-files`, the procedure builds `--existing` from `queryRecords` (`bin/lib/issues/local-store.js`) mapped to the same `{number,title,body}` shape, and passes the current `specs/digest.md` body as the digest input. `_shared/materiality-floor.md:70` already names that body a trusted single-writer string. Filing uses `createRecord`, the writer `/claude-tweaks:capture` uses under `local-files` (`plugin/skills/capture/SKILL.md:306-310`), and never `allocateId` + `writeRecord`. Digest lines append to `specs/digest.md` (`_shared/materiality-floor.md:158`).

### Key Files

- `plugin/skills/tidy/console-backfill.md` — backend gate and filing/digest steps
- `plugin/bin/lib/console/backfill-dispose.js` — filing and digest planning
- `plugin/bin/console-backfill.js` — `dispose` inputs (`--existing`, `--digest-comments`) for the local-files shapes
- `tests/tidy-console-backfill-conformance.test.js` — HELD-line pin (`:55`)
- `tests/bin-lib/console/backfill-dispose.test.js` — local-files planning cases

## Gotchas

- Under `local-files`, a record file and `specs/digest.md` are tracked files. Each landed write needs a commit, which the GitHub path never needs, so the procedure must run in a worktree and commit per write. Otherwise a crash leaves an uncommitted record that the next pass's `queryRecords` still sees. That is fine for dedup, but it must be committed before `console.json` cites it.
- A local record's ref is its id, not `#N` under a GitHub repo. Check that `apply`'s `ref` field and the residue reader (`lib/console/residue.js`) accept the local ref form before the console item is marked settled.
- The digest dedup input differs by backend: comment objects with author association on GitHub, a trusted file body on local-files (`_shared/materiality-floor.md:63-70`). `heldDigestComment` in `backfill-dispose.js` must take the local form without treating it as an untrusted comment.
- The HELD line is pinned verbatim in `tests/tidy-console-backfill-conformance.test.js:55` and also names this record by title. Update both when narrowing the gate.
