# 3462: Add a retirement-sweep check to /build's plan-authoring checks

Origin: reflect full from #3311
Defer-reason: tangential

## Current State

`plugin/skills/build/plan-authoring-checks.md` has no check for a plan that retires a mechanism. That covers deleting a constant, an option, a CLI or a gate.

#3311's plan copied its prose-rewrite file list from the spec's boundary amendment 4, which named three files. About 40 further shipped-skill, doc, journey and test-comment sites still cited the deleted mechanisms. They used phrasings the list never searched for: "warning tier", "40 KB ceiling", "#724 budget", "five bloat signals", `ceiling: Infinity`. The whole-branch review caught them (two Important findings), followed by two residual sweeps.

Evidence: #3311 final-review findings F1–F3 and commits 2347b6b1e, 4572f470b and 981550f92. Cost this session: one fix wave, two residual sweeps and a scoped re-review.

## Deliverables

- [ ] Add a "Retirement sweep" check to `plan-authoring-checks.md`. When a plan deletes a named mechanism, it must carry a task that sweeps every non-history path in the repo for each phrasing of that mechanism: the identifier, the file path, the option literal, the numeric value as prose, and the issue number used as a label. The task's verification grep must name each phrasing.
- [ ] Cite the existing memory rules ("Deleted-rule citation sweep", "Grep retired term repo-wide") as the rationale.

## Acceptance Criteria

1. `plan-authoring-checks.md` names the retirement-sweep check, and a conformance test pins its presence.
2. The check says the sweep's file list comes from the grep's output, never from the spec's named list.

No user-visible change; `/build`'s plan-authoring checks gain a retirement-sweep check, so a plan that deletes a mechanism also sweeps every phrasing of it.
