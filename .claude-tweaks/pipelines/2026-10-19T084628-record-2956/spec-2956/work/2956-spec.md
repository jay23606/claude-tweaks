# 2956: review lens dispatch: a worktree-isolated session cannot write the {ctx-dir}/lens-*.json findings files

Surface: backend

**Related:** #3049, #2955, #3001

## Current State

`/claude-tweaks:review` Step 3 has the orchestrator write two kinds of coordination input into `{ctx-dir}`, the scratch dir `build-review-context.js build` mints:

- `plugin/skills/review/step3-lens-dispatch.md` (Reproduction dispatch, Mode 1): after both agents of a pair return, "write each agent's `findings` array to `{ctx-dir}/lens-{LENS}-agentA.json` / `{ctx-dir}/lens-{LENS}-agentB.json`", then `review-coordination.js categorise-reproduction` reads those two paths.
- `plugin/skills/review/step3-debate-and-refutation.md` (step 1, Detect overlap): the `{lensName: [findings...]}` object is written to `{ctx-dir}/findings-by-lens.json` for `review-coordination.js detect-overlap`.

Under `--run "$PIPELINE_RUN_DIR"`, `{ctx-dir}` is `{run}/review-ctx`, inside the **main checkout** (the run dir is anchored there). A session isolated to a linked worktree (dispatch's two-call handoff, `worktree-always`) is refused both ways of writing there. The `Write` tool is refused by cross-checkout write pinning ("Edit the worktree copy of this file instead"), and a Bash heredoc redirect is refused by the Claude Code harness's worktree-isolation guard as "too complex to verify". Reported on 6.133.0: 3 refused tool calls in an unattended run. The working workaround was writing the JSON elsewhere and passing those paths, which works because both `review-coordination.js` subcommands already take arbitrary file paths (`plugin/bin/review-coordination.js:55-75`).

## Deliverables

1. **Decision (approved in brainstorming, 2026-10-15):** these coordination inputs are written to the session-scoped temp dir (`plugin/skills/_shared/session-tmp-root.md`), never into `{ctx-dir}`, under every session, not only isolated ones. That dir is outside every checkout, so the `Write` tool is never refused there. No sanctioned-writer CLI and no stdin input: stdin would need the JSON in a shell literal or heredoc, the shape the harness guard refuses.
2. `step3-lens-dispatch.md` Reproduction dispatch: resolve each pair's two paths via `node "${CLAUDE_PLUGIN_ROOT}/bin/session-tmp-resolve.js"`. The names carry the review's own `{ctx-dir}` basename (`review-{ctx-id}-lens-{LENS}-agentA.json` / `…-agentB.json`), so concurrent reviews in one session (dispatched subagents share `CLAUDE_CODE_SESSION_ID`) never collide. Then `Write` the arrays there and pass those paths to `categorise-reproduction`.
3. `step3-debate-and-refutation.md` step 1: same treatment for `findings-by-lens.json` (`review-{ctx-id}-findings-by-lens.json`) before `detect-overlap`. The existing "never a fixed shared `/tmp` name" rationale is kept and satisfied by the per-review name.
4. `step3-lens-dispatch.md`'s Agent-scratch cleanup check: the `{ctx-dir}` exclusion list drops `lens-*.json` and `findings-by-lens.json`, which no longer live there, and keeps the pre/post-fan-out status snapshots. The `git status … > {ctx-dir}/pre-dispatch-status.txt` redirect stays (a plain redirect, not refused).
5. A conformance assertion in `tests/bin-lib/review-context/prose.test.js`: neither step file directs writing `lens-*.json` or `findings-by-lens.json` into `{ctx-dir}`, and both name the session-scoped temp dir for them.

## Release Note

Code review no longer stalls on refused file writes when it runs in an isolated worktree session.

## Technical Approach

Prose-only change to two review step files plus one conformance test. The pattern is the one `plugin/skills/wrap-up/review-console.md` already uses for `set-verify-expectations.js --file`: write the JSON with the `Write` tool to the session scratchpad, outside both `$PIPELINE_RUN_DIR` and the worktree, then hand the path to a CLI. The difference here is that no copy back into the run dir is needed, because `categorise-reproduction`/`detect-overlap` consume the files directly and their results already land in `decisions.md` and the routing entries. Resolve paths with the existing `bin/session-tmp-resolve.js` (`NAME=filename` pairs → shell exports), in the same Bash call that uses them, since no shell variable survives across calls.

### Key Files

- `plugin/skills/review/step3-lens-dispatch.md` — Reproduction dispatch write target, `categorise-reproduction` invocation, Agent-scratch cleanup exclusion list
- `plugin/skills/review/step3-debate-and-refutation.md` — step 1 `findings-by-lens.json` write target and `detect-overlap` invocation
- `tests/bin-lib/review-context/prose.test.js` — new conformance assertions

## Gotchas

- Dispatched subagents share one `CLAUDE_CODE_SESSION_ID`, so a bare `lens-3a-agentA.json` in the session temp dir *would* collide across two concurrent dispatched reviews. The `{ctx-dir}` basename in every name is what keeps them apart, so don't drop it.
- `{ctx-dir}` itself is unchanged: the context bundle and status snapshots stay under `{run}/review-ctx`. Only the orchestrator-written coordination inputs move.
- The refusal is the harness's own worktree-isolation guard plus the `Write` tool's cross-checkout pinning, not plugin code (same finding as #2548). The fix routes around both, and nothing upstream is filed from this record.
- `tests/multi-agent-coordination.test.js` reads both step files. Re-run it after the edit in case it pins the old `{ctx-dir}/lens-…` wording.

## Original request

review lens dispatch: a worktree-isolated session cannot write the {ctx-dir}/lens-*.json findings files

**Summary:** Step 3 asks for each agent's findings to be written to `{ctx-dir}/lens-{LENS}-agent{A,B}.json`. When `{ctx-dir}` sits under the run directory anchored to the main checkout, a session isolated to a linked worktree is refused both the Write tool and a heredoc.

**Kind:** Gap

**Affected component:** claude-tweaks review, `skills/review/step3-lens-dispatch.md` (reproduction dispatch), together with `bin/build-review-context.js --run` and `bin/review-coordination.js categorise-reproduction`

**Use case:** A `/claude-tweaks:flow` review step ran in a worktree-isolated session, as dispatch's two-call handoff does. `build-review-context.js build --run <run-dir>` placed `{ctx-dir}` under `<run-dir>/review-ctx`, inside the main checkout. Writing the `lens-*.json` files there failed two ways. The Write tool was refused by cross-checkout write pinning ("Edit the worktree copy of this file instead"). A Bash heredoc redirect to the same path was refused by the worktree-isolation guard as "too complex to verify". The workaround was to write the JSON to the system temp dir and pass those paths to `categorise-reproduction`. `stage-item.js` exists for `staged/`, but nothing equivalent exists for review-ctx scratch files. Cost: 3 refused tool calls, about 2 minutes, in an otherwise unattended run. Possible fixes: a sanctioned writer (a `review-coordination.js` subcommand that takes the findings on stdin and writes `{ctx-dir}/lens-*.json` itself), or `categorise-reproduction` accepting both findings arrays on stdin.

**Definition:** Needed — the two possible fixes (a sanctioned writer, or stdin input to categorise-reproduction) are both viable and no choice has been made.

**Plugin version:** 6.133.0
