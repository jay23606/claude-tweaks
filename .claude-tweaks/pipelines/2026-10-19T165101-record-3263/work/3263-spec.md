# 3263: Add a bin CLI for the PR phase-checklist flip at every pr-first phase exit

Origin: reflect hindsight from #3059

Defer-reason: tangential

## Current State

Every pr-first phase exit (build, test, review, polish, wrap-up) asks the orchestrating agent to flip its PR checklist row by hand, per `plugin/skills/_shared/pr-checklist-refresh.md`'s "Phase-checklist update" section: read the body with `gh pr view`, run `repairPrBody` (`plugin/bin/lib/flow/pr-body.js`), find the `<!-- phases-start -->`/`<!-- phases-end -->` span, flip `- [ ] {phase}`, write a `{run-id}`-scoped temp file, re-read and check its first line, then `gh pr edit --body-file`.

No `plugin/bin/` CLI does this. `ls plugin/bin` has `check-pr-bookkeeping.js` and `flow-preflight.js`, but nothing that writes the checklist. During #3059's `/flow` run (PR #3252), the orchestrator hand-wrote a scratch `pr-phase.js` to avoid recomposing the same six steps at every phase exit. The same prose also governs removing a skipped phase's row (e.g. `polish` on a non-frontend record).

## Deliverables

1. Add a `plugin/bin/` CLI (e.g. `pr-checklist.js --run <dir> --phase <name> [--remove]`) that resolves the PR from `run-state.json`, repairs, flips or removes one row inside the phases span, verifies the run marker, and writes back. Follow the injectable-runner `run(argv, deps)` seam and exit-code conventions of the existing `gh`-calling CLIs.
2. Point `_shared/pr-checklist-refresh.md`'s Phase-checklist update at the CLI rather than restating the steps, keeping the `gh`-absent MCP path documented for sandboxes without `gh`.
3. Tests sized like the neighbouring `tests/bin-lib/` suites: flip, remove, already-checked no-op, missing-markers repair, run-marker mismatch hard stop.

## Acceptance Criteria

- One CLI call flips or removes a single phase row on the run's PR and leaves the rest of the body byte-identical.
- A body whose first line names a different run id is refused with a non-zero exit, and nothing is written.
- `_shared/pr-checklist-refresh.md` cites the CLI. The six-step prose is gone from the `gh`-present path.

## Release Note

No user-visible change. Pipeline phase exits update the PR checklist through one command rather than hand-composed steps.
