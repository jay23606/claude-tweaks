# 3257: Normalize StatusContext entries in the pr-first merge gate rollup read

Verified-as-of: d81250829ae2c3db172448be1f3588da29b78222

Premise-check: ! grep -q StatusContext plugin/skills/_shared/pr-first-merge.md

Origin: reflect full from #3013

Defer-reason: tangential

## Current State

`_shared/pr-first-merge.md` Step 2.5 classifies `statusCheckRollup[]` entries by `conclusion` (red) and `status` (pending). GitHub returns two entry shapes: a `CheckRun` (`status` + `conclusion`) and a legacy commit-status `StatusContext` (`state` = SUCCESS/FAILURE/ERROR/PENDING/EXPECTED, with no `status` or `conclusion`).

Read literally, the rules mishandle a `StatusContext`: a failing one has no `conclusion`, so it never reads red, and its absent `status` is "not COMPLETED", so even a passing one reads pending. A repo whose required check is posted by a commit-status app (e.g. a third-party deploy or review bot) gets a failing check merged past the red path, or a merge that never leaves pending.

#3013 found this while building `bin/pr-checks.js`: `plugin/bin/lib/pr-checks/classify.js`'s `normalizeEntry` maps a `StatusContext`'s `state` onto `status`/`conclusion` before classifying. The merge gate's own read has no such normalization.

## Deliverables

- `_shared/pr-first-merge.md` Step 2.5: one sentence normalizing a `StatusContext` entry (`state` FAILURE/ERROR → red, PENDING/EXPECTED → pending, SUCCESS → completed-green) before the red/pending rules apply, citing `bin/lib/pr-checks/classify.js`'s `normalizeEntry` as the code twin.

- A conformance test pinning that the merge gate's prose names the `StatusContext` normalization and that its state mapping matches `normalizeEntry`.

## Acceptance Criteria

- [ ] Step 2.5 classifies a `StatusContext` with `state: FAILURE` as red and `state: SUCCESS` as green, never as pending.

- [ ] The new conformance test fails when the normalization sentence is removed.

## Release Note

The pr-first merge gate now reads commit-status checks (StatusContext) correctly: a failing status parks the merge instead of passing, and a passing one no longer leaves the merge pending.
