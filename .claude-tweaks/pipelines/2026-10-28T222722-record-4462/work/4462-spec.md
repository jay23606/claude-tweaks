# 4462: reconcile: mirror fast-forward refuses on any untracked file, so a tidy run's own committed trail (or one stray file) blocks main-checkout sync indefinitely

**Related:** #3975, #3855

Origin: /claude-tweaks:tidy close-out 2026-10-27 (run 2026-10-27T055458-tidy-standalone)

Defer-reason: tangential

## Current State

`classifyMirror` (`plugin/bin/lib/reconcile/classify.js`, main) returns `dirty` whenever `git status --porcelain` prints anything, untracked files included, and `mirror-ff.js` then skips the fast-forward. A 2-byte stray file `f` in the main checkout kept the mirror un-synced for more than a day (2026-10-25 to 2026-10-27).

## Deliverables

Approach: Classify the mirror by what a fast-forward would actually touch: tracked modifications block it; untracked files block it only when they collide with a path the incoming range adds (`git merge --ff-only` already refuses that case safely). For tidy, write the post-commit log lines (PR opened, arm outcome) into the committed trail before the commit, or keep them out of the un-ignored files.

1. Narrow the dirty classification so an untracked file that does not collide with the incoming range no longer blocks the fast-forward.

## Acceptance Criteria

- An untracked file at a path the incoming range does not touch no longer stops reconcile's mirror fast-forward.

## Release Note

reconcile keeps the main checkout in sync even when it holds unrelated untracked files, including tidy's own run trail.
