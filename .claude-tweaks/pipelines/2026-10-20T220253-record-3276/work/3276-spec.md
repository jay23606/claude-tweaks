# 3276: Add a security-hardening vertical row to the routine fleet

Surface: infra

Verified-as-of: 3e103acd7

Origin: endorsed by the #3052 continuous-security-scanning evaluation (PR #3275)

Defer-reason: tangential

## Current State

Nothing shipped can put `/claude-tweaks:code-health focus=security-hardening` on a schedule:

- `plugin/skills/routine/fleet.md`'s composition table gives four code-health verticals a scheduled row each: `dead-code`, `test-hygiene`, `abstraction-police` and `experiment-cleanup` (rows 1-4). `security-hardening` has no row.
- `plugin/skills/_shared/routine-template-schema.md` says the `focus` field is unset in every shipped template and is "supplied at fleet-provisioning time". `/claude-tweaks:routine create code-health` takes no focus argument. The fleet is therefore the only shipped way to schedule a focus vertical.
- The daily generalist sweep (fleet row 5, or a standalone `routine create code-health`) never applies this criterion. `plugin/bin/lib/code-health/criteria.js` marks `security-hardening` as "pinned directly by code-health's focus=security-hardening ... never selected via criteriaForArea". The generalist applies `security-logic` and `iac-security` only, one rotated slice per firing.

Today the criterion runs in only two places. `/claude-tweaks:review` Step 6.6 (`plugin/skills/review/focus-criterion-passes.md`) runs it diff-scoped and report-only, and only on reviews of pipeline-built work. Otherwise someone has to run `/claude-tweaks:code-health focus=security-hardening` by hand.

A focus firing that finds nothing costs almost nothing. `plugin/skills/code-health/focus-mode.md` makes a firing with zero candidates a no-op, and dedup against open `by:code-health` issues keeps a repeat firing from filing the same finding twice. The generator (`plugin/bin/lib/code-health/candidates-security-hardening.js`) is shaped for app repos: client and route directory heuristics, AI SDK calls, JWT calls, upload handlers and webhooks. On a repo without those shapes, a daily firing ends at the no-op.

Out of scope here: the other focus verticals without a fleet row (`agent-trust-scope`, `app-store-readiness`, `prelaunch`), any per-commit or diff-scoped firing mode, and any auto-prepared fixes. The #3052 evaluation recommends against the last two.
