# 3736: Move context.js's assigned-run worktree match to case-canonical realpath

Origin: ledger resolve gate (record 3682 ledger row 10)

Defer-reason: pre-existing-outside-diff

## Current State

#3682 moved plugin/bin/lib/hooks/pre-tool-use.js's own path-identity comparisons (teardown own-cwd containment, E1, stamps, dispatch-config) to path-guard's case-canonical `canonicalRealpath`. The teardown gate's assigned-run deny still goes through `ctxLib.findRunByWorktreePath(ctx.cwd, target, ...)` in plugin/bin/lib/hooks/context.js (`worktreeMatches` ~line 546, `findRunByWorktreePath` ~line 562, plus `classifyOwnership`), which resolves both sides with the JS `fs.realpathSync`; on a case-insensitive volume a mis-cased `git worktree remove /path/WT` aimed at a run's assigned, non-own-cwd worktree `/path/wt` misses the match and is allowed. `repoInfo`'s JS-form `repoRoot` also feeds `worktreeMatches`, so the migration needs its own one-sided-mix audit. Surfaced by #3682's final whole-branch review (staged ruling sdd-ruling-2) and ruled out of that branch because the spec names pre-tool-use.js's own sites.

**Related:** #3836, #3811
