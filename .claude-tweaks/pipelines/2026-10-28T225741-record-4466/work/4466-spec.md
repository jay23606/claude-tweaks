# 4466: Below-floor decomposition parents are never closed: the exceeds:false branch says "closes cleanly" but no step closes them

**Related:** #3508, #367

Origin: /claude-tweaks:tidy close-out 2026-10-27 (run 2026-10-27T055458-tidy-standalone)

Defer-reason: tangential

## Current State

`wrap-up/verification-brief-parent-gate.md` says that on `exceeds: false` "the parent closes cleanly: no demo:pending, no brief". Nothing performs that close, though: `/claude-tweaks:demo`'s Approve action is the only place a parent is closed ("nothing else in the system ever closes a parent"), and a below-floor parent never gets a demo gate. Tidy's `parent-gate` scope (`_shared/github-pr-scan-acceptance.md`) also filters below-floor parents out before emitting, so no backstop surfaces them.

## Deliverables

Approach: When the parent gate evaluates `due` with `exceeds: false`, close the parent on the sub-issue-side entry that observed the last sub-issue closing (wrap-up's parent-gate procedure), with a comment naming the sub-issues and their merge commits. Optionally, have tidy's `parent-gate` scope surface any already-stranded below-floor parent as a Close row instead of filtering it out.

1. Close the parent on the exceeds:false branch when every sub-issue is closed (`github-issues`: comment then `gh issue close --reason completed`; `local-files`: `closeRecord`).

## Acceptance Criteria

- A decomposition whose last sub-issue closes below the oversight floor leaves its parent closed, with a comment listing the sub-issues.

Decomposed work below the review floor now closes its parent issue automatically when the last piece ships.
