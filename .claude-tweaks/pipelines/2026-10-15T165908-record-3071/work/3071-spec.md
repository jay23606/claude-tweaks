# 3071: visual-decide `stop` doesn't mark server-stopped on a stale/dead PID

**Related:** #3027, #3130

## Current State

`node --test tests/bin-lib/visual-decide/cli.test.js` fails reproducibly (2/2 isolated re-runs, and in the full `npm test` run) on main tip `5f835e5` (v6.138.0) — not a load-induced flake. The test "stop is stale-PID tolerant (dead PID -> already-stopped, exit 0)" (`cli.test.js:105`) starts a visual-decide server, SIGKILLs its PID, waits 300ms, then runs `stop` expecting exit 0 and a `server-stopped` marker file. The assertion at line 116 (`fs.existsSync(path.join(stateDir, 'server-stopped'))`) gets `false` instead of `true`.

## Deliverables

Fix the `stop` command's stale-PID detection path (dead PID → already-stopped) so it writes the `server-stopped` marker file the same way a live-PID stop does, then confirm the test passes both in isolation and in the full suite.

## Acceptance Criteria

- `node --test tests/bin-lib/visual-decide/cli.test.js` passes in isolation.
- The stale-PID `stop` path writes `server-stopped` in the state dir, matching the live-PID path's behavior.
- No regression in the surrounding `visual-decide` CLI tests (`npm test` stays green).

## Release Note

Fixes `visual-decide stop` so stopping an already-dead server correctly reports itself as stopped.
