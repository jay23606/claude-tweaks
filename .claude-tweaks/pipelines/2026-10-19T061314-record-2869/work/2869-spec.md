## Current State

The original report bundles four friction points from one `/flow` run on 6.132.0 (Windows, worktree-isolated). Checked against this tree:

1. **AC-forwarding sample path unwritable from a worktree session** — already shaped as #3044, which covers exactly this. Excluded from this record.
2. **`computeDiffFacts` input shape vs its documented call — confirmed.** `plugin/skills/build/dispatch.md:19` says to compute diff facts "via `bin/lib/dispatch/ceremony-derive.js`'s `computeDiffFacts` over the branch's `git diff --numstat` output". `plugin/skills/wrap-up/ceremony-derivation.md:30` uses the same phrasing. But `computeDiffFacts(files)` (`plugin/bin/lib/dispatch/ceremony-derive.js:25-29`) takes the parsed `[{path, additions, deletions}]` array, which `parseNumstat` produces. `parseNumstat` is exported from `plugin/bin/lib/blast-radius-cli.js:40,145`. Neither doc names the parser, so following the prose literally passes a raw string and throws.
3. **Circular-dependency warnings on the documented security-hardening invocation — confirmed, but the false-clean claim is not reproduced.** Running `plugin/skills/review/focus-criterion-passes.md:12`'s direct `require` of `candidates-security-hardening.js` emits `Accessing non-existent property 'listTrackedSourceFiles' … inside circular dependency`, along with the same warning for `isGlobDiscoveredTestFile`, `extractModuleExports`, `escapeRegExp` and `listTrackedFiles`. The cause is require order. `candidates-security-hardening.js:143-144` requires `./candidates-dead-code` before `./focus-generators`. `candidates-experiment-cleanup.js:60-61` does the same and also emits warnings when required directly. The ordering rule documented at `candidates-abstraction-police.js:56-68` says to require the registry first, because otherwise Node hands a sibling generator a partially loaded `candidates-dead-code` exports object and its helpers bind to `undefined`. On this repo, `scanSecurityHardening(process.cwd())` still returns a non-empty `{candidates: [...]}`. The scan itself therefore works here, and the generator actually affected by the half-loaded exports is `candidates-abstraction-police.js` in that same process.
4. **`log-decision.js --reversibility` rejects the documented qualifier form — confirmed.** `plugin/bin/log-decision.js:51` accepts only `high|med|low|n/a`. Meanwhile `plugin/skills/_shared/pr-early-run-lifecycle.md:154,307,333` mandates log lines such as `Reversibility: high (branch can be reset/force-pushed).`, and `plugin/bin/lib/log-decision/append.js:51` renders `Reversibility: ${reversibility}.`. The sanctioned writer cannot produce the documented line.

## Summary

A single-record `/claude-tweaks:flow` run (worktree-isolated session, Windows, plugin 6.132.0) hit four plugin-side issues. Item 3 is the most important: it looks like a silent false-clean in review's Step 6.6 security-hardening pass.

## 1. `build/dispatch.md`'s AC-forwarding sample path is unwritable from a worktree session

`skills/build/dispatch.md` ("Standing AC-forwarding verification") tells the run to copy the first reviewer prompt to `$PIPELINE_RUN_DIR/sdd-dispatch-sample.txt`. In a worktree-isolated session the harness's Write tool refuses that path ("Edit the worktree copy of this file instead of the shared-checkout path"), because the run dir is anchored in the main checkout. Workaround used: write inside the worktree, then `cp`. Suggest: document a sanctioned writer (as for `log-decision.js`/`stage-item.js`), or name a worktree-local sample path.

## 2. `computeDiffFacts` input shape vs. its documented call

`skills/build/dispatch.md` ("Whole-branch review model") says to compute diff facts "via `bin/lib/dispatch/ceremony-derive.js`'s `computeDiffFacts` over the branch's `git diff --numstat` output". The function expects the parsed `{path, additions, deletions}[]` array (`blast-radius-cli.js`'s `parseNumstat` shape). Passing the raw numstat string throws `TypeError: (files || []).map is not a function` at `bin/lib/issues/blast-radius.js:91`. Suggest: export or document the parser in the same sentence, or have `resolve-profile.js` accept `--numstat`.

## 3. `scanSecurityHardening` appears to fail silently on a circular import

Running review Step 6.6's documented invocation:

```
node -e "const {scanSecurityHardening}=require('<plugin>/bin/lib/code-health/candidates-security-hardening.js'); console.log(JSON.stringify(scanSecurityHardening(process.cwd())))"
```

printed `[]`, preceded by repeated warnings: `Accessing non-existent property 'listTrackedSourceFiles' of module exports inside circular dependency` (also `isGlobDiscoveredTestFile`, `extractModuleExports`, `escapeRegExp`, `listTrackedFiles`). It returned 0 candidates repo-wide on a repo with an `api/` routes tree. If those helpers resolve to `undefined` because of the cycle, every per-review security-hardening pass reports a false clean. Suggest: break the cycle (lazy require), and have the pass fail loudly when its helpers are unresolved.

## 4. `log-decision.js --reversibility` rejects the documented parenthesised form

`_shared/pr-early-run-lifecycle.md`'s mandatory log lines read e.g. `Reversibility: high (branch can be reset/force-pushed).` Passing that as `--reversibility "high (branch can be reset/force-pushed)"` fails: `--reversibility must be one of high|med|low|n/a`. Suggest: accept a trailing parenthetical, or document that the qualifier goes into `--text`.

claude-tweaks 6.132.0; Claude Code on Windows 11, Git Bash; worktree-isolated session (`worktree-always` policy).
