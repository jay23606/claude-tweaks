# 3495: Resolve both sides of pre-tool-use isPolicyFile with fs.realpathSync.native

Origin: build of #3417 (shared path-guard helper), conformance-lint audit and review

Defer-reason: pre-existing-outside-diff

## Current State

`isPolicyFile` in `plugin/bin/lib/hooks/pre-tool-use.js` compares `realTarget(targetPath)` with `canonicalRepoPath(repoRoot, POLICY_FILE)` for exact equality. Both resolve with the JS `fs.realpathSync` (`safeReal`). #3417 routed `realTarget()` through `plugin/bin/lib/path-guard`'s `resolveLeaf()` but kept the JS form on purpose: switching only one side to `.native` would turn a mis-cased allow into a deny. The JS form echoes input casing on a case-insensitive volume (#3380). So a mis-cased tool-input path to `.claude-tweaks/policy.yml` resolves to a different string than the git-cased `repoRoot`, and the policy-file exemption is denied when it should apply. That direction fails safe, but it is wrong.

## Deliverables

- Resolve both sides of `isPolicyFile` with the case-canonical realpath: `realTarget()`'s `resolveLeaf` call drops its explicit `realpath: fs.realpathSync`, and `canonicalRepoPath`'s parent resolution uses path-guard's `canonicalRealpath`.

- Add a regression test with a mis-cased policy.yml target on a case-insensitive model, using an injected `fsImpl`. The exemption applies after the change and is shown red before it.

- Update the `lib/hooks/pre-tool-use.js` allowlist reason in `tests/path-guard-conformance.test.js` and the `safeReal` anti-pattern row in `.claude/skills/pre-tool-use-gate-exemptions/SKILL.md`.

## Acceptance Criteria

- [ ] A mis-cased absolute path to the repo's `.claude-tweaks/policy.yml` is recognised by `isPolicyFile`.

- [ ] A symlink swapped in for `policy.yml` is still denied, and `npm test` passes.

## Release Note

Editing the project policy file is no longer blocked when its path is typed with different letter casing.
