# 4467: tidy step-7-5: the housekeeping PR merges immediately when the repo has no required checks, and its body is not screened for closing keywords

**Related:** #579, #581

Origin: /claude-tweaks:tidy close-out 2026-10-27 (run 2026-10-27T055458-tidy-standalone)

Defer-reason: tangential

## Current State

step-7-5-worktree-always.md says the arm step runs `gh pr merge --auto` and is "never an immediate merge (checks pending)". On a repository with no required checks GitHub merges at once: on 2026-10-27 housekeeping PR #4458 merged in the same second it was "armed", before any CI run on it. Its `test` workflow then ran only post-merge on main.

## Deliverables

Approach: Before arming, read whether the integration branch requires status checks. With none, `gh pr merge --auto` is an immediate merge, so wait for the PR's checks (bounded watch, as pr-first-merge Step 2.5 does) or leave it unarmed with the reason. Run the same closing-keyword screen build runs use on the composed housekeeping PR body before `gh pr create`.

1. Detect the no-required-checks case before arming and fall back to a bounded check watch, then merge or report.

## Acceptance Criteria

- On a repo without required checks, tidy never merges its housekeeping PR before the PR's own checks complete green.

## Release Note

Tidy's housekeeping PRs now wait for their checks and can no longer close an issue by accident.
