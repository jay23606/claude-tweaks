# 4469: tidy acceptance-gap and parent-gate scans: filter closed records server-side instead of fetching every closed issue up to backlog-fetch-limit

**Related:** #2217

Origin: /claude-tweaks:tidy close-out 2026-10-27 (run 2026-10-27T055458-tidy-standalone)

Defer-reason: tangential

## Current State

`_shared/github-pr-scan-acceptance.md` fetches every closed issue (`gh issue list --state closed --limit backlog-fetch-limit`) and filters for acceptance disposition and the oversight floor client-side. This repo has more than 4400 issues, so the fetch hits the 1000 cap on every tidy run. The scan then warns that `[acceptance-gap]` and `[parent-gate]` results may be incomplete (past the cap, sub-issues default to OPEN, so parents can read as incomplete). That warning appeared again on 2026-10-27. #2217 made the truncation loud but did not remove it.

## Deliverables

Approach: Query closed records already narrowed server-side, for example `gh issue list --state closed --search "-label:demo:approved -label:demo:changes-requested reason:completed"` (plus the oversight-floor labels), then apply the existing client-side checks to that smaller set. Keep the truncation warning for the narrowed fetch.

1. Replace the unfiltered closed-record fetch with a server-side filtered query for records lacking an acceptance disposition.

## Acceptance Criteria

- On this repo a tidy run's acceptance-gap fetch returns fewer rows than backlog-fetch-limit and reports no truncation warning.

Tidy's acceptance checks now cover every closed record without hitting the fetch limit.
